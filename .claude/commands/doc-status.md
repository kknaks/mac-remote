# /doc-status — 전체 문서 현황 확인

## 읽어야 할 파일 (이것만 읽는다)

1. `doc/Spec.md` — 스펙 인덱스
2. `doc/Work.md` — 워크 인덱스

**상세 문서(spec/, work/)는 읽지 않는다.** 인덱스만으로 현황을 파악한다.

## 만들어야 할 파일

없음. 보고만 한다.

---

## 작성 규칙

1. 아래 4가지 관점으로 현황을 보고한다:
   - **스펙 현황**: 전체 스펙 수, 상태별 분포 (Draft/Review/Approved/Done)
   - **워크 현황**: 전체 워크 수, 상태별 분포 (Backlog/In Progress/Review/Done/Blocked)
   - **스펙 커버리지**: Full/Partial/None 분포, Partial인 항목의 미반영 사항
   - **블로커**: Blocked 상태인 워크와 사유
2. 보고 형식은 아래 예제를 따른다.
3. 문제를 발견하면 해결을 위한 다음 액션을 제안한다.

## 예제

### 보고 형식

```
## 프로젝트 현황

### 스펙
- 전체: 5개
- Approved: 3 | Draft: 1 | Review: 1

### 워크
- 전체: 7개
- Done: 2 | In Progress: 2 | Backlog: 2 | Blocked: 1

### 스펙 커버리지
- Full: 2/5 | Partial: 2/5 | None: 1/5
- ⚠ Spec-03: Work-05에서 §5 에러 처리 미반영
- ❌ Spec-05: 워크 미할당

### 블로커
- ⛔ Work-06: Spec-04 리뷰 대기 중 (→ /doc-spec으로 Spec-04 확정 필요)

### 제안 다음 액션
1. Spec-04 리뷰 완료 → Work-06 차단 해제
2. Spec-05에 대한 워크플랜 작성 필요 → `/doc-work`
3. Work-05에서 Spec-03 §5 에러 처리 반영 필요
```

---

## 해야 하는 것 (DO)

- 인덱스의 숫자를 정확히 센다.
- 커버리지 갭(None, Partial)을 명확히 지적한다.
- 블로커가 있으면 해결에 필요한 스킬(`/doc-spec`, `/doc-work` 등)을 안내한다.
- 다음 액션을 우선순위 순으로 제안한다.

## 하지 말아야 할 것 (DON'T)

- 상세 문서(spec/, work/)를 읽지 않는다 — 인덱스만 본다.
- 어떤 문서도 수정하지 않는다 — 읽기 전용이다.
- 추측으로 현황을 보고하지 않는다 — 인덱스에 없는 정보는 "인덱스에 미기록"으로 보고한다.

# /doc-work — 워크플랜 문서 작성

## 읽어야 할 파일 (이것만 읽는다)

1. `doc/templates/Work.tpl.md` — 인덱스 템플릿
2. `doc/templates/Work-detail.tpl.md` — 상세 워크 템플릿
3. `doc/Work.md` — 기존 인덱스가 있으면 (번호 충돌 방지, 의존 관계 파악)
4. `doc/spec/Spec-NN-slug.md` — 이 워크가 구현할 대상 스펙 (**지정된 스펙만** 읽는다)

## 만들어야 할 파일

- `doc/Work.md` — 인덱스 (없으면 생성, 있으면 행 추가 + 커버리지 갱신)
- `doc/work/Work-NN-slug.md` — 상세 워크플랜

---

## 작성 규칙

1. 번호(NN)는 `doc/Work.md` 인덱스의 마지막 번호 + 1이다. 인덱스가 없으면 01부터.
2. slug는 영문 소문자 + 하이픈, 작업을 2~3단어로 요약 (예: `cli-prototype`, `websocket-server`).
3. 워크플랜은 스펙을 **구현 관점으로 분해**한 것이다. 스펙의 "무엇을"을 "어떻게, 어떤 순서로"로 바꾼다.
4. 참조 스펙 체크리스트(§2)는 해당 스펙의 섹션별로 커버 항목을 나열한다 — 빠뜨린 항목이 없는지 추적하는 용도.
5. 태스크(§3)는 한 커밋 단위에 가까운 크기로 나눈다. 태스크마다 완료 시 커밋 해시를 기록한다.
6. 검증 방법(§5)은 실행 가능한 명령어나 구체적 테스트 절차를 작성한다 — "확인한다"가 아니라 "터미널에서 `swift run` 후 창 목록이 출력되는지 확인".
7. 인덱스의 스펙 커버리지 테이블을 반드시 갱신한다.

## 예제

### 인덱스 워크 현황 예시

```markdown
| Work-01 | CLI 프로토타입 | @me | In Progress | 2026-05-24 | | — | Spec-01 |
| Work-02 | 창 활성화 | @me | Backlog | | | Work-01 | Spec-02 |
```

### 인덱스 스펙 커버리지 예시

```markdown
| Spec-01 | Work-01, Work-04 | Full | |
| Spec-02 | Work-02 | Partial | §5 에러 처리 미반영 |
| Spec-03 | — | None | 미착수 |
```

### 참조 스펙 체크리스트 예시

```markdown
| Spec-01 §2 데이터 모델 | WindowInfo 구조체 정의 | [x] |
| Spec-01 §3 계약 | listWindows 요청/응답 | [ ] |
| Spec-01 §5 에러 처리 | 권한 없을 때 빈 목록 | [x] |
```

### 태스크 예시

```markdown
| 1 | WindowInfo 모델 정의 | [x] | a1b2c3d | |
| 2 | CGWindowList 호출 및 필터링 | [x] | d4e5f6a | |
| 3 | 권한 상태 체크 로직 | [ ] | | 다음 작업 |
```

### 검증 방법 예시

```markdown
| 1 | 창 목록 출력 | 터미널에서 `swift run MacHelper` 실행 후 현재 열린 창 목록이 JSON 형태로 출력되는지 확인 | Pass |
| 2 | 권한 미허용 시 | 시스템 설정에서 화면 기록 권한 해제 후 실행, 창 제목이 빈 문자열로 나오고 경고 로그가 출력되는지 확인 | — |
```

## 해야 하는 것 (DO)

- 대상 스펙을 읽고, 스펙의 어떤 섹션을 이 워크가 커버하는지 §2에 명시한다.
- 태스크는 검증 가능한 단위로 분해한다 — "구현한다"가 아니라 "~가 동작하도록 구현".
- 기존 워크와의 의존 관계를 인덱스에 기록한다.
- 태스크 완료 시 커밋 해시를 기록한다.
- 인덱스의 스펙 커버리지를 갱신한다 — Partial이면 비고에 미반영 항목을 기록.

## 하지 말아야 할 것 (DON'T)

- 스펙 문서를 수정하지 않는다 — 스펙 변경이 필요하면 `/doc-spec`으로 안내한다.
- Decision.md를 수정하지 않는다.
- 지정된 스펙 이외의 스펙을 읽지 않는다 — 불필요한 컨텍스트 소비를 막는다.
- 태스크를 너무 크게 잡지 않는다 — "WebSocket 서버 전체 구현"은 안 됨, 분해한다.
- 템플릿의 섹션 구조를 변경하지 않는다.

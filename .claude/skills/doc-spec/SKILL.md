# /doc-spec — 상세 스펙 문서 작성

## 읽어야 할 파일 (이것만 읽는다)

1. `doc/templates/Spec.tpl.md` — 인덱스 템플릿
2. `doc/templates/Spec-detail.tpl.md` — 상세 스펙 템플릿
3. `doc/Decision.md` — 프로젝트 계획·제약·기술 선택 확인
4. `doc/Spec.md` — 기존 인덱스가 있으면 (번호 충돌 방지, 의존 관계 파악)

## 만들어야 할 파일

- `doc/Spec.md` — 인덱스 (없으면 생성, 있으면 행 추가)
- `doc/spec/Spec-NN-slug.md` — 상세 스펙

---

## 작성 규칙

1. 번호(NN)는 `doc/Spec.md` 인덱스의 마지막 번호 + 1이다. 인덱스가 없으면 01부터.
2. slug는 영문 소문자 + 하이픈, 기능을 2~3단어로 요약 (예: `window-list`, `key-input`).
3. 상세 스펙은 **이 기능의 단일 진실 공급원**이다. 모든 역할(프론트/백/임베디드)이 이 문서만 보고 구현할 수 있어야 한다.
4. 템플릿의 11개 섹션을 모두 작성한다. 해당 없는 섹션은 "해당 없음"으로 명시하되 삭제하지 않는다.
5. 계약(§3)은 실제 코드에서 쓸 메시지/API 형식을 JSON 예시로 작성한다.
6. 상태 전이(§4)는 텍스트 다이어그램 + 전이 테이블을 모두 작성한다.
7. 에러 처리(§5)는 에러마다 "처리 주체"와 "복구 전략"을 명시한다.
8. 유저 플로우(§7)는 Happy Path를 먼저, 분기·실패를 그 다음에 작성한다.
9. 인수 조건(§10)은 검증 가능한 문장으로 작성한다 — "~해야 한다"가 아니라 "Given/When/Then" 또는 구체적 체크리스트.
10. 인덱스에 새 스펙을 추가할 때 의존 관계를 반드시 기록한다.

## 예제

### 인덱스 행 예시

```markdown
| Spec-01 | 창 목록 수집 | Approved | — | CGWindowListCopyWindowInfo 기반 |
| Spec-02 | 창 활성화 | Draft | Spec-01 | PID + AXUIElement |
```

### 상세 스펙 헤더 예시

```markdown
# Spec-01: 창 목록 수집

| 항목 | 내용 |
|------|------|
| ID | Spec-01 |
| 상태 | Approved |
| 작성일 | 2026-05-24 |
| 최종 수정 | 2026-05-24 |
| 의존 | — |
| 관련 워크 | Work-01 |
```

### 계약 예시

```markdown
#### 요청 예시
{"action":"listWindows"}

#### 응답 예시
{"type":"windowList","windows":[
  {"id":123,"app":"Arc","title":"탭 12개","frontmost":true}
]}
```

### 유저 플로우 예시

```markdown
### 메인 플로우 (Happy Path)
1. 사용자가 iOS 앱에서 "창 목록" 탭 진입
   ▼
2. 앱이 Mac 헬퍼에 listWindows 전송
   ▼
3. 헬퍼가 창 목록 수집 후 windowList 응답
   ▼
4. iOS 앱이 리스트 렌더링, frontmost 창에 청록 테두리
```

## 해야 하는 것 (DO)

- Decision.md의 핵심 제약과 충돌하지 않는지 확인한다.
- 기존 스펙과의 의존 관계를 인덱스에 명시한다.
- 사용자에게 모호한 요구사항은 질문해서 확정한다.
- 계약 섹션은 양쪽(송신/수신) 모두 JSON 예시를 작성한다.
- 엣지 케이스를 최소 3개 이상 식별한다.

## 하지 말아야 할 것 (DON'T)

- 구현 코드를 작성하지 않는다 — 스펙은 "무엇을"이지 "어떻게"가 아니다.
- Decision.md를 수정하지 않는다 — 기술 선택 변경이 필요하면 사용자에게 `/doc-decision`으로 ADR 추가를 안내한다.
- Work 문서를 수정하지 않는다.
- 템플릿의 섹션 구조(번호, 순서, 테이블 열)를 변경하지 않는다.
- 다른 스펙의 내용을 복사해서 채우지 않는다 — 참조는 링크로.

## 1. 개요

> Mac 헬퍼의 IP:포트를 iOS 앱에 전달하는 페어링 과정. QR 코드 스캔을 기본으로, 수동 IP 입력을 fallback으로 제공한다.

### 범위

- 포함: QR 코드 생성(Mac), QR 스캔(iOS), 수동 IP 입력, 연결 정보 저장
- 제외: 인증/암호화, 멀티 Mac 연결

---

## 2. 데이터 모델

```
Entity: ConnectionInfo
├── host: String     — Mac 헬퍼 IP 주소
└── port: UInt16     — WebSocket 포트 (기본 8765)
```

### QR 코드 페이로드

```
ws://{host}:{port}
```

### 제약 조건

| 필드 | 제약 | 비고 |
|------|------|------|
| host | 유효한 IPv4 주소 | LAN 대역 (192.168.x.x, 10.x.x.x 등) |
| port | 1024~65535 | 기본 8765 |

---

## 3. 계약 (Contract)

### 3-1. 메시지 / API

페어링은 WebSocket 연결 이전에 발생하므로 메시지 계약 없음. QR 코드 / 수동 입력으로 연결 정보를 전달한 뒤 Spec-05의 WebSocket 연결 플로우로 진입한다.

### 3-2. 공유 상수 / Enum

```swift
let defaultPort: UInt16 = 8765
let qrPrefix = "ws://"  // QR 페이로드 형식: ws://192.168.1.10:8765
```

---

## 4. 상태 전이 (State Machine)

### iOS 앱 페어링 상태

```
[미페어링] ──(QR 스캔 성공)──► [연결 시도] ──(성공)──► [페어링 완료]
     │                           │
     ├──(수동 IP 입력)───────────►│
     │                        (실패)
     │                           ▼
     │                     [연결 실패] ──(재시도)──► [연결 시도]
     │                           │
     │                      (포기/변경)
     └────────────────────────────┘
```

| 현재 상태 | 이벤트 | 다음 상태 | 액션 | 비고 |
|-----------|--------|-----------|------|------|
| 미페어링 | QR 스캔 | 연결 시도 | QR에서 host:port 파싱 → WebSocket 연결 | |
| 미페어링 | 수동 입력 | 연결 시도 | 입력값 파싱 → WebSocket 연결 | |
| 연결 시도 | 성공 | 페어링 완료 | ConnectionInfo 저장, 메인 화면 진입 | UserDefaults 저장 |
| 연결 시도 | 실패 | 연결 실패 | 에러 표시 | |
| 연결 실패 | 재시도 | 연결 시도 | 동일 정보로 재연결 | |
| 연결 실패 | 포기/변경 | 미페어링 | 입력 화면으로 돌아감 | |
| 페어링 완료 | 연결 끊김 | 재연결 | Spec-05 재연결 흐름 | 페어링 정보 유지 |

## 5. 에러 처리

| 에러 코드/유형 | 발생 조건 | 처리 주체 | 복구 전략 | 사용자 메시지 |
|---------------|-----------|-----------|-----------|--------------|
| INVALID_QR | QR 코드가 ws:// 형식이 아님 | iOS 앱 | 재스캔 안내 | "올바른 QR 코드가 아닙니다" |
| INVALID_IP | 수동 입력 IP가 유효하지 않음 | iOS 앱 | 재입력 안내 | "올바른 IP 주소를 입력해주세요" |
| CONNECTION_FAIL | 연결 실패 | iOS 앱 | 재시도 또는 재입력 | "Mac 헬퍼에 연결할 수 없습니다. 같은 Wi-Fi인지 확인해주세요" |
| CAMERA_DENIED | 카메라 권한 거부 | iOS 앱 | 수동 입력으로 fallback | "QR 스캔을 위해 카메라 권한이 필요합니다" |

### 재시도 정책

| 에러 유형 | 재시도 | 최대 횟수 | 간격 | 비고 |
|-----------|--------|-----------|------|------|
| CONNECTION_FAIL | Y | 3 | 1초 | 페어링 시 한정, 이후는 Spec-05 정책 |

## 6. 유효성 검증

| 검증 항목 | 규칙 | 검증 위치 | 실패 시 동작 |
|-----------|------|-----------|-------------|
| QR 페이로드 | ws://{ip}:{port} 형식 | Front (iOS) | INVALID_QR |
| IP 주소 | IPv4 형식 | Front (iOS) | INVALID_IP |
| 포트 | 1024~65535 숫자 | Front (iOS) | INVALID_IP |
| 연결 테스트 | WebSocket handshake 성공 | Front (iOS) | CONNECTION_FAIL |

## 7. 유저 플로우 (User Flow)

### 메인 플로우 (Happy Path) — QR 스캔

```
1. Mac 헬퍼 실행 → 메뉴바에서 "QR 코드 표시" 클릭
   ▼
2. 헬퍼가 자신의 IP:포트를 QR 코드로 표시
   ▼
3. iOS 앱 설정 탭에서 "QR 스캔" 탭
   ▼
4. 카메라로 QR 스캔 → ws://192.168.1.10:8765 파싱
   ▼
5. WebSocket 연결 시도 → 성공
   ▼
6. ConnectionInfo를 UserDefaults에 저장
   ▼
7. 메인 화면(창 목록 탭)으로 자동 이동
```

### 분기 플로우

| 분기 지점 | 조건 | 흐름 |
|-----------|------|------|
| Step 3 | 카메라 권한 거부 | 수동 IP 입력 화면으로 전환 |
| Step 3 | 수동 입력 선택 | IP:포트 직접 입력 → Step 5로 |
| Step 6 | 이전 페어링 정보 있음 | 덮어쓰기 |

### 실패 플로우

| 실패 지점 | 원인 | 사용자에게 보이는 것 | 복구 경로 |
|-----------|------|---------------------|-----------|
| Step 4 | QR이 다른 형식 | "올바른 QR 코드가 아닙니다" | 재스캔 |
| Step 5 | 다른 Wi-Fi | "연결할 수 없습니다" | Wi-Fi 확인 안내 |
| Step 5 | 헬퍼 미실행 | "연결할 수 없습니다" | 헬퍼 실행 안내 |

## 10. 인수 조건 (Acceptance Criteria)

- [ ] Mac 헬퍼가 자신의 IP:포트를 QR 코드로 표시할 수 있다
- [ ] iOS 앱이 QR 스캔으로 연결 정보를 파싱할 수 있다
- [ ] 수동 IP:포트 입력으로도 연결할 수 있다
- [ ] 연결 성공 시 정보가 UserDefaults에 저장된다
- [ ] 앱 재실행 시 저장된 정보로 자동 연결을 시도한다
- [ ] QR 형식이 올바르지 않으면 에러 메시지를 표시한다
